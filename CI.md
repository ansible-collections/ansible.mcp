# Continuous Integration (CI)

## MCP Collection Testing

GitHub Actions are used to run the CI for the ansible.mcp collection. The workflows used for the CI can be found in the [.github/workflows](.github/workflows) directory.

### PR Testing Workflows

The following tests run on every pull request:

| Job | Description | Python Versions | ansible-core Versions |
| --- | ----------- | --------------- | --------------------- |
| [Changelog](.github/workflows/changelog.yml) | Checks for the presence of changelog fragments | 3.12 | devel |
| [Linters](.github/workflows/linters.yml) | Runs `black`, `flake8`, `isort`, `mypy`, and `yamllint` on plugins and tests | 3.12 | devel |
| [Sanity](.github/workflows/tests.yml) | Runs ansible sanity checks | 3.10-3.14 (varies by ansible-core) | 2.16, 2.17, 2.18, 2.19, 2.20, devel, milestone |
| [Unit tests](.github/workflows/tests.yml) | Executes unit test cases | 3.10-3.14 (varies by ansible-core) | 2.16, 2.17, 2.18, 2.19, 2.20, devel, milestone |
| [Ansible-lint](.github/workflows/tests.yml) | Runs ansible-lint validation | Latest | devel |
| [Build-import](.github/workflows/tests.yml) | Validates collection build and import | Latest | devel |

### Python Version Compatibility by ansible-core Version

The test matrix is automatically generated by [tox-ansible](https://ansible.readthedocs.io/projects/tox-ansible/) based on ansible-core's Python version support policy. The [tox-ansible.ini](tox-ansible.ini) file controls which versions to skip.

| ansible-core Version | Sanity Tests | Unit Tests |
| -------------------- | ------------ | ---------- |
| 2.16 | 3.10, 3.11, 3.12 | 3.10, 3.11, 3.12 |
| 2.17 | 3.10, 3.11, 3.12 | 3.10, 3.11, 3.12 |
| 2.18 | 3.11, 3.12, 3.13 | 3.11, 3.12, 3.13 |
| 2.19 | 3.11, 3.12, 3.13 | 3.11, 3.12, 3.13 |
| 2.20 | 3.12, 3.13, 3.14 | 3.12, 3.13, 3.14 |
| devel | 3.13, 3.14 | 3.13, 3.14 |
| milestone | 3.12, 3.13, 3.14 | 3.12, 3.13, 3.14 |
